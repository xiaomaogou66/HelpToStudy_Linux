# 📖 使用说明

> 这个库有**两套流程**，各管一段，互不干扰：

```
【日程安排层】管"什么时候学什么、做没做"     ← 每天 2 分钟 / 每周 20 分钟
   首页「📅 今天」 → 打卡 ｜ 周日 /周决策 → Google 日历 ｜ /课表 每学期换一次

【主题学习层】管"这一章怎么学会"             ← 每次学 1-2 小时
   /拆书 → /新主题-拆解与计划 → /学案 → /测试我 → /速查表 → /更新进度
```

# 🚀 首次配置清单（一次性，约 5 分钟）

| # | 在哪 | 做什么 |
|---|---|---|
| 1 | Obsidian → 设置 → **核心插件 → 日记** | 存放位置 `05-日程安排/06-日志`；格式 `GGGG-[W]WW/YYYY-MM-DD`（**一周一个子文件夹**，如 `2026-W38/2026-09-14`）；模板 `02-模板/日记.md`。日记里会自动列出**今日底线 + 今天要做什么**，打开就能勾 |
| 2 | Obsidian → 设置 → **Dataview** | 打开 **Enable JavaScript Queries**（不开的话首页的倒计时/连续天数不显示） |
| 3 | Obsidian → 设置 → **iCal 插件** | 「目标目录」选 `05-日程安排`（别留 `/`，否则每 5 分钟扫一遍教材库）；「保存到 Gist」**关**（走脚本推送） |
| 4 | Google 日历账号 | ⚙ 设置 → **常规 → 时区** 改成 `(GMT+08:00) 中国标准时间` ← 不改的话课会显示到前一天 |
| 5 | Google 日历同步（只有第一次） | 按 `05-日程安排/_脚本/README-首次配置.md` 配服务账号（约 10 分钟，无需发布/验证） |

# ☀️ 每天（2 分钟）

打开 Obsidian → 首页 [[00-使用指南/🏠 首页|🏠 首页]] → 「📅 今天」区块，**两块都能点，点一下即写回来源笔记**：

| 区块 | 内容 | 点一下写回哪 |
|---|---|---|
| **✅ 打卡** | 今天真实日程推导出来的打卡项 | `05-日程安排/06-日志/<周号>/打卡.md` |
| **📚 学习块** | 今天的学习任务（西语/数学科/外语科） | `05-日程安排/06-日志/<周号>/<周号>.md`（周决策，也是日历的源） |

同页还能看到：🔥 连续打卡天数 · 今天打卡 n/m · 四道倒计时 · 下一个检查点。

## 打卡项为什么不是固定的

打卡页（一周一篇，住在**一周一个文件夹**里：`06-日志/2026-W38/打卡.md`）里的条目**按当周真实课表生成**：

| 那天课表里有什么 | 就出现什么打卡项 |
|---|---|
| 任意一节课 | `上课 · 课程名 10:00–12:45`（每节课单独一项） |
| **临时停课**（学校临时通知） | 那天那节课**不计缺勤**：出勤项去掉，改留一条已勾的 `停课 · 课程名 开始–结束` |
| **体育课 / 通识课** | 追加 `课上 Anki 20 分钟`（**只有这两门挂 Anki**） |
| 专业课A / 专业课B / 体育课 / 通识课 | 追加 `课上泛听` |
| **周六**（家教 + 地铁往返） | 追加 `地铁泛听 2 小时` |
| 每天 | `今天没崩（崩了也不补课）` |

- 所以周三（零深度自习日）不会有 Anki 项，体育课开课前也不会凭空出现"课上 Anki"
- 改规则：`05-日程安排/00-配置/底线规则.json`；重新生成：`_脚本/打卡.sh`（**只补缺失项，不清已勾的**）
- 换学期：先跑 `/课表`，再跑一次 `./打卡.sh`
- **临时停课**（学校临时通知）：课表 ics 里那节课加一条 `EXDATE` → 跑 `./打卡.sh`（出勤项换成一条已勾的 `停课 · …`）→ 跑 `./同步日程.sh`（日历里那节课自动取消）。记录表在 `00-配置/底线规则.json` 的 `停课`
- ⚠️ 别删打卡项开头的 `09-14 ·` 前缀（Dataview 靠它认日期、算连续天数）

> **连续天数** = 当天**所有**打卡项都勾上的连续天数。所以"今天没崩"也在里面——
> 即使整天崩掉，只要底线勾了，连续记录就不断（这正是原方案里"崩了只损失深度时间，不损失连续记录"的设计）。
> **计数口径（2026-09-14 定）**：今天勾完 → **+1**；今天还没勾完 → 数字**不动**（不会归零，
> 会标「（截至昨天）」）；只有昨天和今天都没勾满才是 0。
>
> **每天那篇日记里也有这两块**：「✅ 今日底线」+「📅 今天要做什么」，都是**实时镜像查询**，
> 点复选框一样写回源文件 —— 所以在哪里勾都行，永远不会两处不一致。
> 日记里的两块按**那篇日记自己的日期**（`this.date`）查（所以 7 篇各显示各的那天）；
> 首页「📅 今天」才按 `date(today)` 查。
> `Ctrl+P` → 「日记：打开今天的日记」打开就能顺手勾完 + 写复盘。
> 详见 [[05-日程安排/06-日志/说明-怎么打卡|怎么打卡]]。

# 🖥️ 桌面上随手勾待办（Noctalia 小组件）

不想为了勾一个「今天没崩」就切到 Obsidian？**同样的两块内容已经常驻在顶栏**了。

| 入口 | 长什么样 | 怎么用 |
|---|---|---|
| **顶栏** | `☑ 0/5` ＋ **现在该做什么**（`▶ 现在 …` / `⏭ 下一件 22:00 …` / `✓ 全做完了`） | **悬停** → 浮出今天完整清单（正在进行的那条带 `▶`）；**点一下** → 开面板 |
| **面板** | 今天两块清单，逐条可点 | 点那一行即勾选 / 取消；右上角 ⟳ 刷新、✕ 关闭（点面板外面也能关） |
| **桌面卡片** | 一整张**毛玻璃**卡片（空工作区可见） | 点行即写回；点日期那一行 → 进编辑器拖动 |

三处**同一份数据、同一个写回引擎**：读的还是 `打卡.md` + `<周号>.md`，写的还是那一行方括号里的 1 个字符。
所以在桌面勾、在首页勾、在日记里勾，结果完全一样，**永远不会两处不一致**。

## 日常怎么用

1. 顶栏直接告诉你**现在该做什么**：正在进行 → `▶ 现在 …`；还没到点 → `⏭ 下一件 22:00 …`
   （按条目的时间段跟当前时间比，具体规则见下面「顶栏怎么认时间」）
2. 点顶栏出面板
3. 点没做的那一行 → 变灰加底色，笔记里那行同步变成 `- [x]`
4. 点错了再点一下 = 取消

## 顶栏怎么认时间

引擎（`勾选.py`）把每条的时间段解析成机器可读的 `start` / `end`，顶栏拿当前时间跟它比：

| 情况 | 显示 |
|---|---|
| `start ≤ 现在 ≤ end` | `▶ 现在 <任务>`（已完成则为 `✓ 现在`） |
| `现在 < start` | `⏭ 下一件 <HH:MM> <任务>`（取最近的） |
| 都过期了 **且** 全做完 | `✓ 全做完了` |
| 都过期了但没做完 | 退回「第一条没做的」 |

- 只给了开始时间没给结束：按 **1 小时**算；跨午夜（`22:00-01:00`）也能算对
- 顶栏每 60 秒对一次时间，但**只有显示的字变了才重画** —— 一天里真正重绘的次数 ≈ 任务边界次数
- 不想让它认时间：把顶栏组件的 `显示「现在该做什么」` 关掉

## 挪桌面卡片的位置（拖动）

位置/大小由 Noctalia 宿主管理（脚本改不了），进**桌面小组件编辑器**拖：

- **`Mod+Shift+D`**（或 `noctalia msg desktop-widgets-edit`）
- ⚠️ 编辑器和卡片在**同一层（桌面层）** → 开着窗口会被盖住，**先切到空工作区再拖**；拖完 `Esc` 退出
- 桌面卡片里**点日期那一行**也能直接进编辑器

## 写回的安全线

| 措施 | 说明 |
|---|---|
| 只翻转 1 个字符 | `[ ]` ↔ `[x]`；📅 时间、全角空格、行尾原样保留 |
| 写前核对 | 「行号 + 行内容哈希」对不上（别人先勾了 / 文件被重新生成）→ **拒绝写**并弹通知 |
| 原子替换 | 排它锁 + 临时文件 + `os.replace`，写后回读复核 |
| 与 `打卡.sh` 兼容 | 它按「日期 + 条目原文」恢复勾选，**不会抹掉你勾的** |

## 资源占用（为什么可以一直开着）

| 项 | 实测 |
|---|---|
| 界面 | **0 个新进程**（跑在已有的 Noctalia 里） |
| 监听 | 1 个 `inotifywait`，**2.6 MB、闲时 0% CPU** |
| 空闲唤醒 | 服务每 30 分钟 2 次 `stat`；顶栏每 60 秒一次时间比较（纯内存，不起进程） |
| 重绘时机 | 文件变了 / 主题换了 / 顶栏那行字变了才重画；否则不碰 |
| 刷新方式 | 文件事件驱动（inotify），**不轮询文件** |

## 外观怎么调

**文字颜色**：设置 → 插件 → Vault 待办 → `文字颜色`（默认 `on_surface` = 跟随主题）
与 `次要文字不透明度`。

**桌面组件的底**：一直是一层**毛玻璃**，由 Noctalia 注入的标准设置控制，插件不自己铺底 ——
所以调它们就是调整个组件的观感：

| 键 | 管什么 |
|---|---|
| 背景 / 背景颜色 / 背景不透明度 | **整个组件的底**（那层毛玻璃） |
| 整体不透明度 | 整个界面**含文字**一起变淡 |
| 使用图标画勾选框 | 图标 or 文本 ☐/☑ |

> 早期版本插件自己铺了一层实底，结果只能在外圈看到不透明度的变化 —— 所以现在不铺了。

## 两条「不是 bug」的行为

- **打开面板时，顶栏的「活动窗口」标题会空掉** —— 面板会抢键盘焦点，合成器就认为没有窗口被聚焦。
  **控制中心 / launcher 一模一样**（这是 Noctalia 面板的既定行为，不是本插件引起）。
- **中部的「媒体」组件没播放时会自己隐藏** —— 它带 `hide_when_no_media`；放点音乐就回来了。

## 换机器 / 重装怎么装回来

插件在**库外**（`~/.local/share/noctalia/plugins/vault-todo/`），所以库内留了一份源码：
`05-日程安排/_资源/noctalia插件/vault-todo/`。恢复步骤（含顶栏与桌面实例的配置写法）见其中的 `README.md`。

更省事的办法：**独立安装包** `~/发布/noctalia-vault-todo-<版本>.tar.gz` —— 解压后
`./install.sh --dry-run` 先演练，再 `./install.sh` 一键装（插件 + 引擎 + 顶栏 + 桌面实例 + 重启都做了，
且幂等、会先备份）。包里另有 `INSTALL.md`（前提 / 手动步骤 / 验证 / 排障 / 卸载）。

# 🗓️ 每周（20 分钟，周日 12:05）

**起床第一件事，别先拿手机。**

```
① Claudian 输入  /周决策
     → 自动检索：上周完成率 / 崩过几天 / 各科进度 / 到期的检查点
     → 自动生成 05-日程安排/06-日志/<周号>/<周号>.md（周决策，带 📅 的任务行）
     → 自动建同一个文件夹（预建 7 篇日记）+ 写 打卡.md
     （**一周一个文件夹**：周决策 + 打卡页 + 7 篇日记，全在一起）
② 核对 + 填 ____（它会告诉你需要补几处）
③ 终端跑：cd ~/obsidian_vault/05-日程安排/_脚本 && ./同步日程.sh
     → 秒级进 Google 日历
④ 之后六天不决策
```

**三条铁律**（写进 `05-日程安排/日程安排.md`）：

1. **周日 12:05 的周决策不许跳** —— 起床后第一个动作如果是"想想要干什么"，结果一定是玩耍
2. **崩了不补课** —— 缺口就是缺口，第二天照表走。`/周决策` 也**不会**把上周没做完的搬过来
3. **降级只砍语言，绝不砍数学科和 GPA** —— 观察指标：连续 2 周 `actual_hours` < 15h

> **每周固定还有 3h 课程复习**（周四 22:00 / 周五 21:05 / 周日 22:30 各 1h，都在晚饭之后）——
> **不算深度自习**（23h 不变），由 `/周决策` 自动排进笔记和日历。详见 [[05-日程安排/03-时间预算与周表|03 · 时间预算与周表]]。

> 每周日写完周决策，**顺手把上一周的 `actual_hours` 填上**（在周决策笔记的 frontmatter）。
> 这个数字是铁律三唯一的判断依据，也决定要不要降级。

# 📚 每次学习（1–2 小时）：主题学习 5 步

## 1. 新建主题

- `Ctrl+Shift+N`（或 `Ctrl+P` → 「➕ 新建学习主题」），输入主题名
- 自动在 `03-学习主题/<主题名>/` 生成主页并打开

## 2. 拆书（Step 1：解决教材超过上下文限制）

> 教材几十万到几百万字，AI 一次读不完。先拆成"一章一个文件"再学。

1. 双击 `_工具/拆书.sh`（或在终端运行），选择 / 拖入教材 **PDF**
2. 工具调用 MinerU 云端识别（公式转 LaTeX，每日免费 1000 页），再按章节标题切分：
   - `04-教材分块/<书名>/章节XXX-*.md`：一章一个文件
   - `04-教材分块/<书名>/01-全书大纲.md`：**全书章节大纲 + 进度勾选清单**
3. 首次使用先跑一次 `_工具/设置MinerU令牌.sh` 保存 Token
4. 想调整拆分不耗额度：把 `00-MinerU解析全文.md` 交给 `_工具/拆书.sh`（自动识别为全文重切分）

> Linux 版只保留 MinerU 拆书：请提供 **PDF**（扫描版 / 数学书均可）；EPUB / Word 不支持。

也可以在 Claudian 输入 `/拆书`，让 AI 判断用哪种方式并执行。

## 3. 一键生成水平拆解 + 学习计划（Step 2 + Step 3 已合并）

1. 打开主题主页，Claudian 输入 `/新主题-拆解与计划 <主题名>`
2. AI 自动完成并写入笔记：
   - **五级水平拆解**：完全初学者 → 基本理解 → 实际使用者 → 问题解决者 → 自信实践者
     （每级含概念、里程碑、练习、常见错误、自检题）
   - **二八定律学习计划**：20% 核心概念 + 10 个 Session（每 Session 2 小时，
     含目标、关键概念、练习、免费资源、复习题）+ 最终项目
3. 结果保存为 `【主题名】-学习计划.md`（首页「学习计划直达」会自动列出）

> 教材已拆好时，先 @ 它的 `01-全书大纲.md` 再运行命令，计划会更贴合教材。
> **例外**：长期项目型科目（如西语 A0→B2 跨 61 周）不必硬套 10 个 Session，
> 可以让计划直接采用阶段划分（P0–P4），仍然用 `/学案` 逐课生成。

## 4. 学与记（每次 2 小时）

1. Claudian 输入 `/学案 <章节> <主题名>` → 生成**学案 + Session 记录**整合文件
   （frontmatter `type: session`，可被 `/更新进度` 识别）
2. 照学案学：知识点详解 → 做自测题 → 勾「本次完成情况」
3. 「卡住的地方」写进文件末尾，下次直接问 AI
4. 学完输入 `/更新进度 <主题名>`：自动更新主页进度 %、当前级别、薄弱点，
   并帮你勾选 `01-全书大纲.md` 里学完的章节

## 5. 让 AI 考我（Step 4）

`/测试我 <主题名>` —— AI 一次一个问题、逐题打分、指出理解边界，
结果存入 `测试记录.md` 并更新主页「薄弱点」。

## 6. 一页速查表（Step 5）

`/速查表 <主题名>` → 生成 `速查表.md`。之后每次学习/考试前先花 5 分钟扫一遍。

# 📆 每学期：换课表

```
把学校新导出的 .ics 拿到手 → Claudian 输入  /课表  → 完事
```

`/课表` 会：体检新表（**先 --dry-run，绝不直接写**）→ 列出「新增/消失的课」→
备份旧表到 `课表-历史/` → 差量同步。

- 文件约定：`05-日程安排/_资源/日历/课表-当前.ics`（唯一真源）
- **四道安全阀**：解析出 0 条 → 中止；数量骤降 >50% → 中止；`--skip-ics` / `--skip-tasks` 可分开跑
- `📚` 开头的自习块**自动过滤**（那些由 `/周决策` 管，不会重复）
- 支持 `UNTIL` / `COUNT` / `INTERVAL`（隔周课）/ `EXDATE`（放假停课）/ UTC 时间
- 一学期跑一次通常只要几十次 API 调用（按 iCalUID + 内容指纹差量对账，约 43 秒）
- 详见 `05-日程安排/_脚本/README-首次配置.md`

# ❓ 常见问题

**Q：日历里看不到新日历 / 课跑到前一天去了？**
A：两件事分别查：
1. **别的端登录的账号**是不是日历所属的那个账号（用无痕窗口只登一个账号验证）
2. **账号时区**：Google 日历 App **按账号时区显示**。账号不在 `Asia/Shanghai` 时，
   12:05 的课会显示成 00:05、周五的课会跑到周四 —— 看起来就像"课丢了"。
   改：calendar.google.com → ⚙ 设置 → 常规 → 时区。
> 正在用非 Google 客户端（苹果/微软/小米日历）？Google 的二级日历不会自动出现，
> 要用日历设置里的「秘密地址（iCal 格式）」去订阅（那个地址等于私钥，别外传）。

**Q：AI 总是忘了我学到哪？**
A：每次对话前打开主题主页并 @ 它。进度永远写在笔记里，AI 只负责读和写。

**Q：书太厚，大纲还是太多？**
A：学不完就拆前几章先学；`01-全书大纲.md` 里勾掉学完的章节，剩下的就是"还没学"清单。

**Q：想让 AI 用 DeepSeek 更省钱？**
A：在 Claudian 设置里启用 Claude 提供方并安装 Claude Code CLI，
再配置 Anthropic 兼容的 DeepSeek 端点（需自行确认端点可用性）。
不配置时，默认 Codex 后端即可直接使用。

**Q：我用的 niri（无桌面环境），怎么启动拆书？**
A：终端运行 `_工具/拆书.sh` 即可；安装库时已注册应用启动器，
也可从 fuzzel / rofi 等启动器搜索「拆书（MinerU）」。
目录/文件选择由 zenity 提供（环境配置.sh 会自动安装 zenity、xdg-utils）。

**Q：Dataview 报 `Unrecognized function name` 怎么办？**
A：**0.5.68 的函数名以插件源码为准，和网上教程不完全一致。** 常用对照：

| 你可能想写 | 0.5.68 里的正确名字 |
|---|---|
| `avg(x)` | **`average(x)`**（`avg` 只是数组方法 `rows.score.avg()`） |
| `min/max/sum` | `min` / `max` / `sum` ✅ 同名 |
| `rounded(x)` | `round(x)` |
| `len(x)` | `length(x)` |
| 空值处理 | `nonnull(x)`、`choice(条件, 真值, 假值)` |

查完整名单（从已装插件里提取，最权威）：
```bash
python3 -c "import re,os;print(sorted(set(re.findall(r'DefaultFunctions\.(\w+)\s*=',
  open(os.path.expanduser('~/obsidian_vault/.obsidian/plugins/dataview/main.js'),encoding='utf-8',errors='ignore').read()))))"
```
另外：**别名里有括号/百分号必须加引号** —— `progress AS "进度(%)"` 可以，`AS 进度(%)` 会解析失败。

**Q：打卡项不对 / 想加一条底线怎么办？**
A：改 `05-日程安排/00-配置/底线规则.json`（有注释：`每节课` / `触发`（条件 → 打卡项）/ `每天都有` / `例外.停课`），
然后重跑 `_脚本/打卡.sh` —— 只会补缺失项，**不会清掉你已勾的**。别直接改生成出来的打卡页，下次会按规则重写。

**Q：`/周决策` 生成的任务行格式能改吗？**
A：**不能改**。同步脚本靠 `- [ ] 内容 📅 YYYY-MM-DD HH:MM - HH:MM`
（日期 + 同一行的时间区间）生成定时事件。也不要写 `🔁`（不支持循环，
每周写一遍本身就是重新决策），不要手改 `05-日程安排/06-日志/<周号>/<周号>.md` 里任务的日期格式。

**Q：把任务勾了以后，Google 日历里会消失吗？**
A：默认**不会**——改成 `✅ 标题` 留在日历里（能看到自己做了什么、也方便复盘）。
想让它消失：`05-日程安排/_脚本/sync_gcal.py` 的 `同步配置.json` 里把
`"completed"` 改成 `"drop"`。

**Q：同步脚本报 `TimeoutError` / 卡 20 秒？**
A：你走了 http 代理但 venv 里缺 PySocks（httplib2 会静默直连）。修：
`_工具/.venv/bin/python -m pip install -r 05-日程安排/_脚本/requirements.txt`

**Q：拆书卡在「上传解析中」反复重试，报 `context deadline exceeded`？**
A：那是扫描版 PDF 单份体积太大（比如 200 页 / 127 MB），上行没传完就被工具的超时掐断。
现在脚本会自动处理：先用 Ghostscript 把扫描页降到 200 DPI（191 MB → 63 MB，
识别精度不受影响，结果缓存在 `_工具/.mineru_cache/`，同一本书重跑不压第二次），
再按「≤200 页 **且** ≤25 MB」分块上传，单份上传超时还会自动对半切小重传。
网络仍慢就再调小（第二个参数会透传）：
`_工具/拆书.sh 某本书.pdf --mineru-chunk-mb 8`；
不想耗额度先看分块计划：`_工具/拆书.sh 某本书.pdf --mineru-dry-run`；
想保留 300 DPI 原件直传：`--mineru-dpi 0 --mineru-chunk-pages 40`。

**Q：每章标题是装饰字体（如《某外语教材》的 UNIDAD 第X课），整本书只认出 3 章？**
A：现在**默认就会自动纠正**（`--chapter-end-pattern auto`）：先从正文里挖
「每章都出现、且只出现一次」的小节（间隔还要求均匀），拿在每章最靠后的那个
（如「作业 (Trabajos de casa)」）当收尾锚点，章界 = 锚点之后的下一个章名行/
章首小节（如「课文 TEXTOS」）；只有比通用识别切出更多章时才采用，
切完还会校验每章字数。《某外语教材》两册这样就能正确切出 16 课。
想自己指定：`--chapter-end-pattern '习题\s*\(Ejercicios'`，必要时再配
`--chapter-title-pattern`（章起点特征）与 `--chapter-start-pattern`（第一章起点）；
不想要这套策略：`--chapter-end-pattern off`。重切不耗额度：
`_工具/拆书.sh "04-教材分块/<书名>/00-MinerU解析全文.md"`

**Q：关系图谱里为什么会出现好几个「🏠 首页」（或一堆同名笔记）？**
A：因为**关系图谱的节点标签 = 文件名，不带文件夹路径**。只要不同文件夹里有同名文件，
图谱里就会长出好几个长得一模一样的节点 —— 不是 bug。最常见的来源就是**备份副本**。

- **备份一律放在库外**：`~/obsidian_backups/`（一周/一次一份，命名 `日期-改动说明/`）。
  **不要在库内建 `_备份/`** —— 库内的任何文件都会被 Obsidian 索引、搜索、画进图谱。
- 已经在库里并且想去掉：设置 → 文件与链接 → **已排除的文件** 加 `_备份`；
  或图谱 → **筛选** 填 `-path:_备份`（只影响显示，文件还在）。
- `04-教材分块/<书名>/_备份/` 是拆书脚本自己留的旧分块（脚本写死的位置，别动）——
  它同样会造成同名重复节点，用上面的图谱筛选 `-path:_备份` 一并盖掉。

> 备份放库外还有个隐性好处：同名文件不会让 `[[短链接]]` 的解析变得有歧义。
